# 本地工具精简与性能调整设计

状态：方案草案；本轮只交付设计和实施计划，不修改产品行为。
基线：V1.4.339 / 1c1da941b16c7a971a1029fd3cdc1a868019a100。
项目根目录：F:/codex/AI绘画Tag工具箱/work/drawing-feedback。
配套计划：[分阶段实施计划](../plans/2026-09-22-local-tool-slimming.md)。

## 1. 产品目标与取舍

这是一个单机、本地保存数据的绘图辅助工具。用户主动配置 AI 服务和 ComfyUI。设计重点是打开快、操作顺畅、生成任务能接着修改、关键数据能保存和恢复。

本次采用“收敛现有实现 + 按需读取 + 精确查询索引”。比较过三种路线：

| 路线 | 代价与收益 | 决定 |
| --- | --- | --- |
| 只删安全检查 | 能缩短少量路径，但大对象传输、重复记录和全量扫描仍然存在 | 不单独采用 |
| 在现有模块里减少副本、缩小接口、增加必要索引 | 每阶段可运行，可使用已有测试和存档 | 推荐 |
| 重写存储、换数据库、引入通用 Worker/RPC/虚拟列表框架 | 改动大，新增生命周期和迁移负担，尚无对应收益证据 | 不列入默认实施 |

明确约束：

- 保留 Electron、CommonJS、现有 JSON 文件与图片文件；默认不加第三方依赖。
- 不建设隐私治理、内容审查、多用户权限、通用授权平台或新的监控系统。
- 成人开关是显示偏好，不是 AI、识图、翻译或保存的权限开关。
- 接口返回调用方真正需要的字段；列表不附带原图、完整对话或全部生成历史。
- 核心数据各有一个写入者；缓存可丢弃、可重建，不是第二个数据源。
- 每个可独立验收的改动单独提交；一个对话轮次交付一个最终测试包。
- 同一问题修改 2～3 次仍未收敛，按项目规则停下报告。
- 必跑 npm run check；默认不跑启动应用的慢测试。性能测量按相关里程碑进行，不每个提交全量重跑。
- 不自动推送或发布；版本号执行时按实际最新版本递增，不在方案中预占版本。

仅保留直接关系到使用结果的检查：文件能否解析、ID 是否存在、写盘失败是否可见、关闭是否保存、旧请求是否会覆盖新结果、AI/Comfy 请求是否重复提交。保留现有 contextIsolation 和 nodeIntegration 设置，不把它们列为性能重构目标。

## 2. 基线与证据边界

数据来自前一轮 V1.4.339 测量，不是本轮新测。当前测试基线为 660 项通过。
原始数据在 work/performance-audit-v14339；下表保留足够的数值，实施者不必依赖该未跟踪目录才能理解目标。

| 场景 | 已观察结果 | 解释 |

| 翻译参考词，20 个常见词首次 / 重复 | 277 / 31 ms | 不含模型推理 |

| 图库列表 5 张图 | 返回对象含约 64.1 MB Base64 字符、1 MB 缩略图 | 是逻辑载荷，不是已测网络流量或实际复制内存量 |
| 5 张图的图库选择 | 11 ms | 当前样本较快，但调用路径仍重建全部卡片 |
| 10,000 收藏的编辑并重建索引 | 303 ms | 合成数据；JS DOM 初次渲染 163 ms，不能代替 Chromium 绘制 |

尚未复现用户报告的约 3 秒冷启动。调用日志、图片和基础库计时存在父子调用包含关系，不可相加承诺“必省几秒”。

需要纠正前述审查中的表述：

1. assistant 和 runtime 暴露的是同一个监视器的别名，不是两个独立日志文件；真正重复的是监视器正文与对话、任务里的内容。
2. adult 与 searchable 含义不同；categoryCode 也可能是模型分类数据，不能按同名字段全部删除。
3. restoreUserState 当前返回状态，不是不可用空桩；删除前迁移实际调用。
4. tags.js 中包含构建辅助函数，不代表启动执行了整个种子构建器；总模块 require 曾测得约 36 ms，不能把它说成主启动瓶颈。
5. 精确查表不能直接替代子串、模糊搜索和中文高亮定位。
6. 生成任务与消息关联有实际用途。历史消息不能只引用一个会不断变化的 job，否则续轮后旧消息也会显示成新结果。

## 4. 具体设计

### 4.1 关键日志替代全量诊断副本

监视器只保留固定字段：

~~~javascript
{
  requestId, rootRequestId, parentRequestId,
  sessionId, messageId, jobId,
  kind, tool, model, status,
  startedAt, endedAt, durationMs,
  apiCalls, usage: { inputTokens, outputTokens, totalTokens },
  usageScope, httpStatus, error: { code, message }
}
~~~

- 不记录请求头、配置对象、系统提示词、消息正文、原始响应、图片、完整事件数组。
- 无需先拿到所有数据再递归脱敏：记录生成点直接构造上面的字段。
- 接口短错误文字最多 300 字符；解析失败必要的结果片段最多 512 字符，附到对应对话的失败说明；独立翻译/识图则留在当前结果面板。普通摘要日志不保存结果正文。
- 保留实际失败状态、耗时与每次 API 返回的 usage；总用量只汇总 API 叶子调用，父任务汇总不重复加算。
- 最多 200 条、总文件不超过 512 KiB。开始时内存展示；结束时合并写盘，关闭时 flush；无每个流式片段写日志。
- 使用新文件 debug/ai-call-summary.json。旧 ai-calls.json 不自动加载、不覆盖、不删除；这是有意停止显示旧全量监视记录，不影响旧对话。
- 摘要日志在首屏就绪后恢复，按 requestId 合并，当前运行记录优先，不能被稍晚返回的旧文件覆盖。
- 界面只有一个摘要日志入口；详细调度通过 messageId 定位对话。独立服务调用没有 messageId 时显示摘要，不制造虚假的对话。
- 默认不增加“详细日志模式”等新配置。

### 4.2 图片元数据、缩略图和原图分开

目标接口如下。已有内部接口先兼容，当前页面调用迁完后立即删对应桥别名。

~~~javascript
imageRepository.listGallery({ offset: 0, limit: 80, query: '', order: 'oldest' })
// => { items: ImageMeta[], total, hasMore }

images.getMeta(imageId)                    // => ImageMeta | null
images.getThumbnail(imageId)               // => Promise<{ imageId, mime, dataUrl } | null>
images.readBytes(imageId)                  // 内部 => Promise<Buffer | null>
imageRepository.getOriginalBytes(imageId)  // 页面 => Promise<Uint8Array | null>

ImageMeta = {
  imageId, displayName, width, height, mime,
  source, status, hasThumbnail, createdAt
}
~~~

- 元数据禁止返回 bytes/dataUrl/完整 PNG metadata/analysis。不为列表名词变化新增并行图片仓库。
- 启动只恢复图片索引，读取原图文件次数为零；原图读取在预览、识图、下载、源图上传或导出时发生。
- 同一 imageId 同时读取合并成一个 Promise。原图缓存用字节上限 64 MiB；超大的单张图只服务当前操作，不永久占缓存。
- 页面只为可见卡片与上下约一屏预取缩略图，同时最多 2 个请求。先用已有 thumbnailDataUrl；无缩略图时按需用现有缩略图生成路径生成并持久化一次。
- 大图预览用 Uint8Array → Blob URL；关闭或换图释放 URL。AI 需要 Base64 时在发送边界临时转换，不把 Base64 长期塞进列表。
- 缺失文件显示不可用，保留引用与提示，不能把它当空图成功返回。
- 保留图库/会话共享图片的关系逻辑，以免删除一个引用就删掉另一处仍在用的图片。
- 文件型生产存储以 .bin 为原图唯一持久副本；是否停止重复 blob 写入在兼容 getBlob 读取迁完后处理，内存测试存储可继续使用 blob。

### 4.3 页面按需渲染

- 默认 Tags 页不预先渲染整段聊天、提示词编辑页和图库。
- AI 页首次进入再加载当前会话；后续靠内容版本失效。不能只删除 start() 里的 renderTalk 而不补首次进入逻辑。
- 图库选择只更新目标卡的 class、aria-pressed、选择数量与按钮，不调用 listGallery 或 preview。
- 收藏复用已有栏目懒加载：先呈现最多 4 个首屏栏目，其余占位，滚动接近时加载；健康提示只读 status/迁移摘要。
- Tags 先保留现有分页和初始 400 项；“把 400 改成 200”不叫虚拟列表。若加载更多到 2,000 项后的实测渲染任务超过 50 ms，再实现按视口保留卡片的窗口化。
- 动态换行的 Tag 卡片不直接套固定行高；虚拟化列为条件任务，需覆盖缩放、键盘、文本选择和定位。默认不引入虚拟列表依赖。

### 4.4 查询表和缓存

先解决已经量到的线性扫描，不先构建通用索引平台：

1. 翻译精确索引放在 translation.js，按现有 normalizeTag 规则将英文、中文、别名映射到有序 Tag ID。重复别名保留当前“第一个可用记录”行为。
2. 输入未知词可一次查表返回未命中；本地字典翻译复用同次查询结果，模型成功时不再提前计算完整 fallback。
3. 索引第一次打开翻译页时生成。测量首建时间单独列出，不能藏在热查询数字里。
4. 对内容、中文名、别名、searchable 等有效变化失效；选择、复制、会话事件不使索引重建。复用库的 change 通知，不增加另一份全局业务 revision。
5. 角色浏览先用轻量身份/作品关系做排序与作品计数。全量角色详情、可选服装和审计资料仅进入详情或生成确需资料时读取；避免首次作品统计 clone 34,122 份完整角色。
6. 作品统计缓存按实际内容变化、显示偏好、作品查询失效。改名字/关系/撤销都必须生效。
7. 普通 Tag 模糊检索保留现有标准化、32 项结果缓存和分页。只优化单条编辑后的局部失效；不把 substring 查询改成精确 Map 查询。
8. 搜索命中高亮仍依据原字符串 UTF-16 偏移；排序、同名角色归属、原始 Tag 字节不变。

### 4.5 缩小检查范围

| 边界 | 调整后检查 |
| --- | --- |
| 受控内置基础库 | 构建、打包时完整检查；生产只查版本/结构入口，建立必需索引 |
| 本机用户文档读取 | 一次格式/引用检查；坏文件报错并保留 |
| 选择/取消/清空选择/标记复制 | 检查受影响 ID、类型和已有关系，不遍历基础库 |
| Tag/分类/角色关系修改 | 一处负责；先保留完整用户覆盖文档检查，再按收益考虑增量 |
| 导入和迁移 | 一次完整检查与一次提交，保留失败重试 |
| AI 返回工具参数 | 入口一次解析与参数检查，防止模型格式错误直接破坏执行 |
| 程序内部同一数据传递 | 直接传经过该边界确定的结构，取消重复净化和递归复制 |

选择类快路径只适用于已成功初始化且由单一命令队列维护的文档。仍写原文件、仍按保存成功后发布变更；不为了快而提前向 UI 报“已保存”。

不删 task-router、Tags-only 禁止出图、续轮锁、反馈改动范围和重复 Comfy 提交保护。这些约束直接保障用户要求，不属于内容审查。

### 4.6 成人偏好与接口清理

- 规范记录字段使用 adult 和 searchable；includeAdult 是查询参数。nsfw/isAdult 等旧字段只在输入适配处转换一次。
- adult 仅决定列表、推荐参考词和计数的展示筛选；显示开关不能拒绝用户明确给出的 Tag、角色 ID、图片、翻译或生成请求。
- UI 查询在统一 library query 处筛选一次；角色详情/生成按明确 ID 获取时不重复拒绝。移除 primary-tools 的“宿主允许且 AI 参数再次允许”门槛。
- searchable 表示是否参加发现搜索，不等于隐藏/私密权限；已引用内容不因此丢失。
- 可保留名称、路径等本地调试字段中确有用途的内容；无用途字段不收集。无需为保留过大的对象再编写多层清洗。
- bridge 只公开实际页面使用的方法。images/imageStore 合一；日志接口合一；未使用的 all/getAll、低层 schema 暴露在核对动态调用与测试后删除。
- 37/42 等接口数量只能作为盘点，不作为“越少越好”的 KPI。删除一个别名也不等于删一个功能。

### 4.7 聊天与生成状态

- 保留原生 assistant/tool 调用与结果配对，保留本轮用户原话、brief、来源图和当前 Tag。
- 对话 events 只存一份；activity 是 UI 临时投影。toolCalls 的展示摘要与供模型续聊的 transcript 用途不同，不直接删除 transcript。
- 会话侧栏只读目录摘要；流式更新消费当前消息回调，时间线复用同一消息，禁止每 50 ms clone 两次完整会话。
- 先减少无效复制与保存，保留现有持久化格式。结果、取消、失败、切换和退出立即 flush；流式中继续按已有间隔合并，记录未刷盘窗口。
- request-manager 持有当前状态；status-manager 中只镜像请求的 Map 可删除，状态 UI 投影从 request-manager 与当前事件生成。
- generation job 仍是唯一可续轮的生成执行状态；每条完成消息保留不可变的轮次引用和少量文字结果。

~~~javascript
message.generationRef = {
  jobId, roundId, candidateIds, selectedCandidateId
}
message.delivery = { prompt, negative, outcome, completedAt }
~~~

仅 jobId 不够。轮次引用确保查看旧消息不会跟随最新候选漂移。历史 prompt/negative 属于用户已经看到的交付快照，允许保存这份小而必要的冗余。

作业跨消息更新、导出导入与引用清理只有在包含旧存档的往返测试通过后才切换；不以“只有一个空会话”为由删恢复能力。

### 4.8 启动与构建

先减掉实际工作，再优化可见性：

- 首屏就绪后加载摘要日志；图片只恢复元数据；隐藏页不抢首屏。
- 构建期全面验证内置库，运行时不再每次验证所有已打包基础记录。保留建立 Map 与用户覆盖层检查，不能宣称这些时间全部消失。
- 不为了 runtime/build 两个名字增加空包装。preload 按需 require 实际工厂，旧素材 reader 留在构建入口；模块 require 约几十毫秒，不是第一优先级。
- Promise.resolve()/setTimeout 包住大循环不会减少 CPU 工作，不能称为后台加载。按现有 catalog.ready 生命周期分阶段安排，输入未就绪显示准确状态。
- 若这之后基础库仍占启动 >200 ms，且总体热启动改善不足 20%，再试一个“紧凑运行包”：构建一次，轻量搜索数据与可选详情分开；不同时维护新旧两套运行数据。
- 紧凑包验证结果相同、无需数据库；若 parse 和同步索引仍造成明显长任务，再比较单个专用 Worker，达不到收益就不采用。Worker、SQLite、分片存储均不是必做阶段。

## 5. 性能目标及验证口径

以下是实施目标，不是本轮已经实现的承诺。时间阈值只在同一机器、同一数据、同样缓存条件的专门性能测量里比较；单元测试用计数和行为断言，避免时钟抖动造成假失败。

| 项目 | 目标 |
| --- | --- |
| 当前数据热启动 | 同口径中位数改善至少 20%；参考目标从约 1.49 秒到不高于约 1.2 秒 |
| 冷启动 | 记录点击/进程启动、壳显示、Tag 可用三点；先复现 3 秒，不提前承诺 1 秒 |
| 基础日志 | 200 条文件不超过 512 KiB，首屏不读旧全量日志 |
| 图片启动 | 原图读取 0 次；元数据列表不含原图载荷 |
| 图库选择 | list/preview 额外调用 0；无关卡片 DOM 节点保持同一对象 |
| 翻译精确引用 | 索引就绪后 40 个未收录词 <20 ms；索引首建目标 <400 ms，单列报告 |
| Tag 选择 | 内存提交 p95 <10 ms；完整文档校验调用 0 次 |
| 角色页 | 首次目标 <200 ms，热统计 <5 ms；全部角色仍可分页到达 |
| 收藏栏目 | 初次最多 4 栏；单项健康提示不展开所有收藏 |
| 长对话流式 | 500 条历史下每次增量不读取全会话；单次渲染 p95 目标 <16 ms |

图片/缓存优化新增内存应与被消除副本一起报告；不得只用更大的无界缓存换时间。

## 6. 数据迁移和交付

默认批次不改变用户数据格式。图片仍使用当前 .bin 和索引；选择仍写 tag-library-v2.json；对话和生成任务先保持原键。只有摘要日志新建小文件，旧详细日志保留原地，不再自动恢复。

高风险的消息/job 去重在独立批次做：

1. 保存一次版本化原文件备份。
2. 旧消息可读；新引用必须能从同一导出包恢复 job 与图片关系。
3. 不同时写两套权威状态。以临时文件完成后再替换，切换失败使用旧文件。
4. 回退应用到旧版时使用该批次前的配套备份；保留新文件供后续恢复，不用旧版盲读新格式。
5. 不自动清理所谓孤儿图片或用户旧对话。

每批完成：针对性测试、npm run check、相关性能对比、中文小提交。执行轮次结束才同步最终 exe、app.asar、源码和版本到桌面，等待人工测试；文档方案这轮不重新打包。

## 7. 阶段边界

A：摘要日志与基线；
B：轻量图片接口和按需显示；
C：查询索引与页面缓存；
D：重复检查、成人偏好和接口收敛；
E：聊天/任务状态与保存；
F：启动与构建收敛。

先交付 A+B，每阶段内部允许若干小提交。完成 C、D 后复测整体，再决定 E 的存储变更和 F 的紧凑包是否值得做。不要求把所有条件任务都做完才交付。

工程收据：code-quality-workflow；ST-A0；知识快照 2026-08-18。目标为减少重复工作，边界为本机数据可保存与生成语义不丢失，验收为功能测试与同口径实测。未采用额外设计目录或框架。
